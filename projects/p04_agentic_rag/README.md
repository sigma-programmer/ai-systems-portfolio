# P04 — Self-Correcting Agentic RAG

> You can stop RAG from confidently lying.

## Problem
Vanilla RAG retrieves top-k, stuffs a prompt, and trusts whatever comes back. It fails in three
predictable ways: (1) the question needs facts from several passages or uses different words than
the corpus, so one retrieval pass misses; (2) the corpus simply does not contain the answer, but
the generator answers anyway from loosely related text; (3) the generator drifts — wrong number,
dropped "not", swapped name, citation pointing at the wrong document. This project makes every
one of those failure modes observable and handled: multi-step retrieval with query rewriting,
per-sentence citations verified against their sources, and calibrated abstention.

## Architecture
```
 question
    │
    ▼
 ┌──────┐  decompose multi-part questions into self-contained "needs"
 │ plan │  ("…and who is its CEO?" → "Who is Lumora's CEO?")
 └──┬───┘
    ▼
 ┌───────────────────────── retrieval loop (≤ max_steps) ─────────────────────────┐
 │  HybridRetriever (BM25 ⊕ HashingEmbedder cosine, convex fusion)                 │
 │        │ top-k per unmet need                                                    │
 │        ▼                                                                         │
 │  RelevanceGrader: IDF-weighted concept coverage (+synonyms) of need in passage   │
 │        │                                                                         │
 │  every need has a relevant passage? ──yes──► exit loop                          │
 │        │ no                                                                      │
 │  QueryRewriter: decompose → synonym expansion → keyword extraction (escalating) │
 └────────┬────────────────────────────────────────────────────────────────────────┘
          ▼                      no relevant passage for any need ──► ABSTAIN ("closest
 AnswerGenerator ─► claims ("sentence [doc_id]")                       passage lacks 'X'")
          ▼
 HallucinationDetector: entailment(claim, cited passage)
   coverage · numbers · number+unit binding · negation count · entity presence
          ▼
 Repair: re-cite unsupported claims to a passage that entails them; drop the rest;
         regenerate empty needs with the constrained extractive generator
          ▼
 Confidence = σ(9·(0.45·retrieval + 0.35·needs_answered + 0.20·grounding − 0.55))
          ▼
 answer (+ unanswered parts)  or  "I don't know …"         + full Trace of every step
```
Every stage is a `Protocol` with an offline heuristic implementation and an LLM implementation
(`LLMGrader`, `LLMRewriter`, `LLMGenerator`, `LLMEntailment`) that talks to any `aikit.LLM`.

| Module | Responsibility |
|---|---|
| `retriever.py` | Okapi BM25 + dense hybrid over the bundled corpus |
| `grader.py` | `TermStats` (synonym-aware concept IDF) and relevance graders |
| `rewriter.py` | decomposition with pronoun resolution, synonym expansion, keyword extraction |
| `generator.py` | `Claim`, extractive generator, LLM generator + citation parser |
| `verifier.py` | heuristic / LLM entailment, `HallucinationDetector` |
| `adversarial.py` | `HallucinatingGenerator` (red team) and `ParaphrasingGenerator` |
| `controller.py` | `AgenticRAG` loop, repair, confidence, `Trace`, `RAGResult` |
| `dataset.py`, `bench.py` | labeled set and metrics |

## Key design decisions & tradeoffs
* **IDF-weighted concept coverage as the relevance signal.** A passage about the CEO matches
  "Lumora" and "CEO" of *"What is the salary of the Lumora CEO?"* but not "salary" — and because
  "salary" never occurs in the corpus it carries the maximum IDF, so coverage collapses to 0.45 and
  the system abstains, naming the missing concept. Cosine similarity alone cannot do this: the
  near-miss passage is *very* similar. Synonym matches earn 0.8 credit, exact matches 1.0.
* **Score fusion, not RRF.** Convex fusion of max-normalised BM25 and raw cosine keeps absolute
  magnitudes so a weak best hit stays weak; RRF would make every rank-1 look equally good.
* **Plan first, rewrite on failure.** Multi-part questions are decomposed up-front (otherwise a
  passage covering half the question can satisfy the whole); rewriting escalates only for needs
  that remain unmet, which bounds cost: answerable questions take 1 step, unanswerable ones use
  the full budget before abstaining.
* **Contradiction checks beat overlap.** "The Beacon battery lasts 36 hours" overlaps its source
  ~90%. Overlap-only verification misses it; explicit checks for numbers, number+unit binding
  ("18 minutes" vs "18 hours"), negation-count mismatch and foreign entities catch it.
* **Repair before abstain.** Mis-cited but true claims are re-cited; corrupted claims are dropped
  and the need is regenerated by the extractive generator (which copies source sentences and so
  cannot hallucinate). Generator unreliability still lowers confidence via the grounding signal.
* **Tradeoff — heuristic entailment is brittle on paraphrase.** 16% of meaning-preserving
  rewordings ("tallest" for "highest") are flagged as unsupported. That is the safe failure
  direction (drop/recite rather than hallucinate) and the `LLMEntailment` judge is the drop-in fix.
* **Honesty note.** The thresholds were tuned on this labeled set; treat the perfect slices as a
  dev-set result, not a generalisation claim. The adversarial and paraphrase slices are the
  stress tests.

## How to run
```bash
AIKIT_OFFLINE=1 .venv/bin/python projects/p04_agentic_rag/demo.py
.venv/bin/python -m pytest projects/p04_agentic_rag
cd projects/p04_agentic_rag && PYTHONPATH=../../common:. ../../.venv/bin/python -m agentic_rag.bench
```
```python
from agentic_rag import AgenticRAG
r = AgenticRAG().run("When was Lumora founded and who is its CEO?")
print(r.answer, r.confidence); print(r.trace.pretty())
```
Plug in Claude: `AgenticRAG(grader=LLMGrader(llm), generator=LLMGenerator(llm), checker=LLMEntailment(llm))`
with `llm = aikit.get_llm()`.

## Benchmark (measured, offline, deterministic)
Labeled set: 24 answerable (4 multi-part, 3 needing synonyms), 12 unanswerable near-misses,
12 adversarial questions × 5 seeds = 60 runs with a generator that corrupts every claim and adds a
fabricated one (140 injected claims).

| Metric | Value |
|---|---|
| Answer accuracy (answerable) | **1.000** (multi-part 1.000) |
| Abstention precision / recall | **1.000 / 1.000** |
| Citation precision (cited doc ∈ gold) | **1.000** |
| False-flag rate on clean extractive claims | 0.000 |
| Hallucination catch rate (140 injected) | **1.000** (number, unit, negation, entity, miscite, fabricated: all 1.0) |
| Hallucinations leaked into final answers | **0** |
| Adversarial answer accuracy after repair | 0.983 (1 miss: a re-cited true-but-off-target sentence satisfied the need) |
| Paraphrase false-flag rate (19 true reworded claims) | 0.158 |
| Confidence Brier score | 0.0011 |
| Avg retrieval steps / rewrites issued | 1.67 / 24 (all on unanswerable questions) |
| Latency mean / p95 per question | 0.65 ms / 0.99 ms (adversarial 1.08 ms) |
